The story, the data, and the model behind the Heart Disease Predictor

What it does

The Heart Disease Predictor is a machine learning web app that estimates a patient's likelihood of having heart disease from seven clinical indicators: age, sex, chest pain type, maximum heart rate achieved, ST depression (oldpeak), ST slope, and thalassemia status. Enter the values on the predictor page and the trained model returns a risk result along with a confidence score.

Building and comparing the models

Rather than committing to a single algorithm up front, this project trained and evaluated several classic classification models on the same clinical dataset to see which one generalized best: Logistic Regression, K-Nearest Neighbors, Support Vector Machine, Decision Tree, Random Forest, and Gaussian Naive Bayes. Each model was trained on the same train/test split and scored on accuracy so the comparison stayed fair.

Somewhat surprisingly, the simplest model in the lineup, Gaussian Naive Bayes, came out ahead of the more complex ensemble and margin-based models, reaching roughly 80% accuracy right out of the box. That result made sense on reflection: Naive Bayes tends to do well on smaller clinical datasets with roughly independent numeric features, which is a close match for this dataset's shape.

Squeezing out more performance with hyperparameter tuning

Once Naive Bayes was chosen as the strongest candidate, the next step was to stop using its default settings and actually tune it. A grid search was run over the model's smoothing parameter (var_smoothing) using cross-validation, testing a range of values on a logarithmic scale to find the setting that best balanced bias and variance for this dataset.

The search compared each candidate configuration on held-out folds rather than the training data alone, so the selected parameters reflect what actually generalizes, not just what fits the training set. The best-performing configuration from that search is the one currently powering the live predictions on this app.
